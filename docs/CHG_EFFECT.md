# 为什么只有 67W：温度伪装能救回什么，不能救什么

> 依据：`2026-11-12 13:29~13:30` 的充电统计截图（31%、34.8℃、4.157V、
> 67.66W 电池侧 / 73.5W 输入、状态栏 65W）+ 一加 15 充电 DT + 内核源码。
> 这一轮把「逆向出来的温度伪装原理」从"猜一个值"改成"实测扫一遍"。

## 1. 先算一下这条充电线在哪

- 4.157V 是单芯电压，2S 整包 8.314V；67.66W ÷ 8.314V ≈ **8.14A** 电池电流。
- 一加 15 的 120W 是 11V × 11A ≈ 121W；31% SOC、34.8℃ 时电池侧应该能到 ~100W。
- 截图里输入只有 **73.5W**，状态栏也显示 **65W** → 这条线是 65W 级（PD/PPS），不是 SuperVOOC 120W。

所以「67W」不是模块没生效，是**适配器/协议给到这里就没了**。

## 2. 三条限流线，这条充电一条都没碰到

| 限流 | 阈值（DT/源码） | 当时 34.8℃ / 31% |
|---|---|---|
| 电池温度降流 | `oplus,ufcs_strategy_batt_high_temp = <400 420 430 ...>`，**40.0℃ 起**每 2℃ 降一档 | 还差 5.2℃，**未触发** |
| 机身温度分桶 | `oplus,temp_range = <0 50 120 160 210 380 440>`，`normal_high = [210,380)` = 21.0~37.9℃ | 常温本来就在最高电流段，**换不了段** |
| SOC 降流 | `oplus_spec,ufcs_high_soc = 90` | 31%，**远未到** |
| 适配器/协议 | usb `voltage_max × current_max` | 73.5W 输入 ≈ 65W 级，**天花板** |

结论：`oplus_dbg_tbat` 伪装**只解除温度限流**。这次没有温度限流可解除，所以它必然「无感」——
不是参数没写对，是没有可解的限流。

## 3. 那这个原理什么时候才有用

只有当**真的过热**时：

- 机身（shell）> 38℃ → 曲线掉进 `warm` 段，伪装回 `normal_high` 才有增益；
- 电池 > 40℃ → `BATT_TEMP_VOTER` 把电流压到 6A/5A/3A 档，这时只有改电池温度
  （`gauge_dbg_tbat`，会连保护一起骗）才救得回来。

常温 + 65W 头 = 两个条件都不满足，任何温度伪装都不会让功率变大。

## 4. v1.4.6：把「猜值」改成「实测」

不同机器/不同 DT 的分桶表不一样，手写 360（闭源模块的值）或 220（本模块旧的自动值）
都可能踩错段。新增一条命令，**按 DT 分桶表逐档实测电流**：

```sh
su -c 'sh /data/adb/modules/feather_tune/bin/ctl.sh charge sweep'
# 可选：第二参数是每档等待毫秒数（默认 4000，范围 50~15000）
su -c '... ctl.sh charge sweep 3000'
```

输出形如：

```
sweep: node=/sys/module/oplus_chg_v2/parameters/oplus_dbg_tbat orig=0 settle=4000ms
try=25 temp=2.5℃ ibat=-8140mA power=67.7W
try=85 temp=8.5℃ ibat=-8142mA power=67.7W
try=140 temp=14.0℃ ibat=-8138mA power=67.7W
try=185 temp=18.5℃ ibat=-8141mA power=67.7W
try=295 temp=29.5℃ ibat=-8139mA power=67.7W
try=340 temp=34.0℃ ibat=-8137mA power=67.7W
best=25 best_power=67.7W worst_power=67.7W
restore=0
verdict: 各温度档电流差异 <3%，温度不是当前瓶颈（适配器/协议上限约 65.0W）
```

- 如果各档电流**有差异** → 会直接告诉你最优值，`ctl.sh set accel_tbat <值>` 固定它；
- 如果各档**没差异** → 说明温度不是瓶颈，别再折腾伪装温度，去查适配器/协议。

扫描结束会把节点还原成进入时的值；扫描期间守护进程不跑自己的 tick（同一线程），
所以不会两边抢着写。

## 5. `charge why` 新增三行

```
adapter: 65.0W (usb voltage_max=20000mV × current_max=3250mA)
input: 73.5W
peak: on=68.2W off=96.4W
headroom: batt 34℃ → 降流线 40.0℃（还有 6.0℃）
```

- `adapter` 是**协议天花板**（协商电压 × 规格电流），低于 90W 时会额外打一行提示；
- `input` 是 usb 侧实测输入功率；
- `peak` 把**亮屏/息屏峰值分开**记：120W 这种档位基本只在息屏给。如果 `off` 明显高于 `on`，
  说明 67W 是厂商的亮屏限流，模块没有任何用户态节点能改；
- `headroom` 是离电池温度降流线还有多少度——正数就说明「温度伪装没东西可解」。

### 5.1 120W 原装头也只到 67W 的两种可能

1. **亮屏限流**（最常见）：锁屏 3~5 分钟，`peak.off` 若明显高于 `peak.on` 就坐实；
2. **厂商的「先冲后收」曲线**：插上瞬间 ~95W，几十秒后回落。锁屏也不回升就是这种；
3. 都不可能时再查协议（`usb/real_type`）与线材。

## 6. 想吃满 120W 的正确姿势

1. **原装 120W 头 + 原装线**（第三方 65W 头物理上到不了）；
2. SOC < 60%、机身 < 37℃、电池 < 40℃；
3. `ctl.sh charge why` 里 `adapter` 应该 ≈ 121W，`power` 应该 100W 上下；
4. 如果 `adapter` 仍只有 65W：换线 / 换头 / 看协议有没有协商上
   （`cat /sys/class/power_supply/usb/real_type`，或 `charge probe` 里的 usb 行）。

## 7. 安全边界（没有改）

- 电池 ≥ 45℃：停止伪装，交回厂商限流；
- 电池 ≥ 50℃：降一档；≥ 52℃ 再降；≥ 54℃ 暂停；
- 退出 / 拔线 / 卸载：所有伪装与限流节点还原。
